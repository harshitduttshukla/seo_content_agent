Manager-Friendly Explanation: How the System Works in Plain English

Designed for executive stakeholders: how your business context becomes governed, high-ranking content.

1

You connect your website

The system crawls your pages, headings, and links. It learns what already exists on your website so you never produce duplicate or competing content.

2

You upload or target keywords

The system automatically clusters related keywords together into topic groups so each article ranks for dozens of terms simultaneously.

3

AI drafts your initial SEO Strategy (Version 1 Kickstart)

The AI reviews your website data and keywords to produce an initial strategy draft. The AI does not publish or finalize it automatically. You review the business context and goals in the form, make edits, and click "Save as Version 1". Future changes save as Version 2, Version 3, and so on.

4

The system builds your visual Content Map

Your content is organized into Content Pillars (core authority topics) and Subtopics (supporting pages), showing exactly how each article supports the main pillars through internal linking.

5

You draft content in a guided TipTap editor

For every planned page, the system provides an automated SEO Content Brief with recommended word count targets, target keywords, and brand tone guidelines.

6

Governed AI assistance with mandatory Human Approval

When you ask the AI to "Optimize this article and add relevant internal links", the AI never overwrites your live text directly. Instead, it reads the document, finds approved link targets, and proposes a visual diff. Nothing changes until you click "Approve", after which a new version is created in history and verified for accuracy.

3. Backend Request Lifecycle & Security Flow

Every incoming request follows strict zero-trust security and transaction boundaries.

Step 1 • Authentication
OIDC / JWT Verification
Decodes Bearer tokens against the JWKS endpoint. Rejects expired or tampered signatures with HTTP 401 Unauthorized.
app.security.oidc
Step 2 • Multi-Tenant RBAC
Tenant Isolation & Scoping
Verifies user membership in Organization and Project. Unauthorized requests return 404 (anti-enumeration) to prevent data existence leaks.
AuthorizationService
Step 3 • Schema Contracts
Pydantic v2 Validation
Enforces strict schema models, type coercion, and extra-field bans. Invalid payloads return 422 Unprocessable Entity with specific field errors.
Pydantic Contracts
Step 4 • Transaction & Context
Service & Session Boundary
Propagates actor ID into PostgreSQL (SET LOCAL app.current_user_id). All queries explicitly filter by organization_id.
async with session.begin()
Step 5 • Audit & Event Outbox
Tamper-Evident Outbox
Inserts audit records and writes domain events to the outbox table in the same atomic database transaction, preventing dual-write inconsistencies.
AuditWriter & OutboxWriter
Step 6 • API Response
Standardized Envelope
Wraps outputs in a consistent JSON envelope with metadata and request IDs. Never exposes raw database models or internal stack traces.
ApiResponse[T]

4. AI Orchestrator & Governed Tool Execution

Multi-step autonomous execution with isolated read steps and gated write steps.

Component 1
IntentClassifier
Detects intent (multi-step tasks, SEO audits, link opportunities, outlines, or rewrites) from user prompts using semantic heuristics.
IntentClassifier
Component 2
WorkflowPlanner
Translates user intent into an ordered sequence of maximum 8 steps. Sequences read steps before write proposals.
WorkflowPlanner
Component 3
ContextBuilderService
Assembles prioritized background context (brief, SEO guide, brand rules, document blocks) within an 8,000 token budget.
ContextBuilder
Component 4
ToolRegistry & Executor
Manages 14 typed tools with risk ratings. Read tools run autonomously; write tools generate patches requiring human approval.
ToolRegistry (14 Tools)
Component 5
Approval Gate
Pauses the workflow in WAITING_FOR_APPROVAL state. The AI cannot mutate text without explicit operator approval.
WAITING_FOR_APPROVAL
Component 6
VerificationService
Post-mutation check inspecting the database to confirm the version number bumped and modified blocks match the proposal.
VerificationService

5. SEO Strategy AI V1: Lifecycle & Versioning

The AI draft is ephemeral; user review and explicit saving establishes Version 1.

Phase A
Uncommitted Draft State
New projects start with an uncommitted initial template. Status is DRAFT and no business strategy is active yet.
Phase B
AI Kickstart (Zero DB Writes)
Backend collects project metadata, active websites, top crawled URLs, and keywords. AI returns structured JSON. Database is NOT touched.
Phase C
User Review & Edit
The AI draft loads into the strategy form. The user reviews and edits business context, personas, competitors, and SEO objectives.
Phase D
Save as Version 1
User clicks "Save as Version 1". Backend updates the initial record in-place, sets status to ACTIVE, and logs strategy.created.
Phase E
Future Edits (Version 2+)
Subsequent saves create new rows in seo_strategy_versions, incrementing version = 2 while preserving Version 1 history.
